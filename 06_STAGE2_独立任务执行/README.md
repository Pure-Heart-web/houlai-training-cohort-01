# Stage 2 独立任务执行训练包 — Simulation

本包是 DS03 工业询盘的合成训练，不代表真实客户、交付、客户批准或软件试用授权。两名成员分别为 A 技术、B 实施；姓名由创始人实际分配。状态初始均为 **NOT_EXECUTED**，无成绩、无完成记录。既有测试、历史评分和工程候选资料均不是本轮执行证据。

## 使用顺序

1. 阅读本页、[案例资料](01_案例资料.md)、[工程摘录](资料/工程代码摘录.md)及岗位任务卡；有获授权的 GitHub Issue 时记录其链接，否则使用本地任务卡。无需联网。
2. 各自先写独立分析，再按各自 [Prompt Map](04_AI辅助学习.md) 使用 AI；保存提问、建议、至少两项质疑和本人结论及最高帮助等级。不得将完整题目交给 AI 生成最终答卷。
3. A、B 分别完成任务和交付报告；随后按 [协作事件](05_跨岗位协作.md) 逐项交接，记录责任、证据和下一步。客户邮件仅写模拟草稿，禁止发送。
4. 创始人使用 [验收与记录](06_创始人验收.md) 逐人验收、引用本轮证据并记录是否触发否决；再填写下一阶段能力评估。成绩只有在实际验收后填写。

所有任务卡均含背景、任务、资料、AI 方法、交付物、验收、常见错误、反例和个人复盘。可复制 [提交模板](07_提交模板.md) 到获授权的个人工作区填写；不要改写模板为虚构完成记录。训练可用文本阅读完成，不启动 FIX-009 或任何 HTTP 服务，不读取真实客户数据、密钥，不调用真实模型 API，不改正式代码，不提交、推送或部署。AI 学习如使用获授权的交互工具，仅输入本包合成文本，不执行 API 调用；不可用时先记录问题及独立判断，AI 环节标记未执行。

## 判定边界

- VERIFIED 表示相关证据经所述核验，不表示客户批准、业务最终决定或生产可用。
- BLOCKING_CONFLICT 保留冲突及来源，不自动选值；需有权人员澄清和记录后再决定。
- 页面未保存的 B 不等于服务器已保存 B；保存成功需可复核的确认。导出源和时点须核实。
- FIX-009 仅按本包的假设场景和静态资料分析；工程候选不等于生产可用，也不宣称已运行或通过本轮测试。
- 分数 ≥8/10 且四项安全否决均未触发、证据完整才可判本阶段达标；不自动授予 L3/L4 或试用授权。独立能力依仓库 [能力等级与帮助记录](资料/能力等级与帮助记录.md) 及新变体证据另判。

GitHub 用户可直接阅读本包 `资料/` 中的合成输入、静态摘录和来源清单，无需访问相邻仓库；摘录不构成可运行项目。

# A 技术任务卡 — Simulation

**背景**：DS03 的模拟询盘和附件有流量差异；需要能追溯的技术分析与跨岗位交接。FIX-009 仅作工程候选的静态分析。

**任务**：先独立画从输入到规则结果的数据流，列模块职责、输入输出和信任边界；查证 DocumentSnapshot、CandidateFact、ValidatedFact、RuleResult 在资料中的对应实现或缺口，说明来源、证据定位、验证及规则输出之间的关系，区分概念与代码事实。分别构造设备身份、Revision、工况、单位四种反例，写输入、为何不能直接比较、保留证据及下一步。分析事件 3 中保存、编辑、导出可能出现的不同结果，给出静态核验方案、预期和未验证项；不能声称行为已实际观察。形成工程风险清单，含风险、影响、证据、负责人、缓解与验证方式，提交技术报告及给 B 的交接。

**可用资料**：[案例资料](01_案例资料.md)、[工程代码摘录](资料/工程代码摘录.md)与[来源清单](资料/来源清单.md)、[协作事件](05_跨岗位协作.md)；不得启动服务或调用 API。

**AI 辅助方法**：先写个人数据流与反例，再使用 [A Prompt Map](04_AI辅助学习.md) 查漏；记录关键建议、至少两项有理由的质疑、来源核验和本人结论及最高帮助等级。

**交付物**：数据流图或表、四角色与模块职责对照、四个反例、保存/编辑/导出状态表和静态核验方案、风险清单、技术报告、AI 记录、个人复盘及交接；可用 [提交模板](07_提交模板.md)。

**验收条件**：每个结论能追溯至本轮引用或明确假设；四类反例均涉及比较前提；冲突不自动选值；区分未保存页面与服务器状态、导出来源待核实；报告说明未运行、候选非生产及待验证事项；交接包含负责人、证据和行动。

**常见错误**：把抽取候选直接当作批准事实；因同设备名或数字相同就忽略版本、工况、单位；拿历史测试当本轮证据；把页面 B 当已保存。

**反例**：P-103 Rev A 的 85 m³/h 与 P-104 Rev A 的 58 m³/h 即使字段名相同，也不能仅凭数字断定同一设备的冲突；必须先核实设备映射。

**个人复盘**：原本判断是什么？哪项证据改变或限制了判断？AI 哪两条建议受质疑、为何？还有什么不能确定？下次怎样独立验证？

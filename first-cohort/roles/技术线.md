# 技术线：受控 Issue 的代码交付
模拟训练｜只操作个人独立副本，禁止修改生产仓库。

## 执行
1. 阅读 [Issue](../technical-lab/ISSUE.md) 和起始代码，独立解释输入、输出、边界及至少两种修改方案，再选方案并说明理由。记录初始认识快照及计划。
2. 在本仓库根目录，将 `first-cohort/technical-lab` 复制到自选个人工作目录；以下命令在副本执行：
```bash
git init
git add ISSUE.md checker.py test_checker.py
git commit -m "chore: record training starter"
git switch -c codex/inquiry-check
python3 -B -m unittest -v > RED.txt 2>&1
```
RED 命令预期非零；保留完整输出再继续，不能用未运行的日志。Git 若未设置身份，按本人的训练身份设置后再提交，不能冒用他人；不需要远程服务。
3. 修改 `checker.py`，不得删测试、改预期或硬编码样本；按需 AI，记录最高帮助。运行同一公开测试生成 GREEN 日志，再补充与自己方案有关的反例/边界测试并回归。
```bash
python3 -B -m unittest -v > GREEN.txt 2>&1
git diff --check
git diff -- checker.py
git add checker.py
git commit -m "feat: implement numeric comparison"
```
4. 写 [本地 PR 记录](../technical-lab/PR模板.md)，提交代码、公开测试原件、RED/GREEN 输出、回归、`git diff` 或提交记录及业务四卡台账。

## 专业验收
公开六测通过；测试文件原件和预期保留；关键分支可解释；不同输入仍工作；缺失、负容差和无容差的行为符合 Issue；他人在干净目录可复现；PR 写触发、改变、验证、限制及帮助。导师在私有受控环境运行未见输入，再现场给一个反例让本人预测和解释；公开通过不能代替此步骤。独立考核受方向性提示则转练习。
